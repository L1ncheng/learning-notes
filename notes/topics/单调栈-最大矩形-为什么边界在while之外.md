# 单调栈 · 最大矩形：为什么"边界"必须在 while 之外取

## 0. 一句话

> **弹栈弹掉的是"比我高或相等"的柱子，它们在定义上就不可能是我左右边界；
> 边界是弹完之后幸存下来的栈顶。**

### 目的：单调栈是为了"找到一个边界数字"

写单调栈之前先明确它要产出什么 —— **不是什么抽象结构，就是一个数（边界下标）**：

| 要产出的东西 | 怎么说 |
|---|---|
| **产出** | `left[i]` / `right[i]` = **一个下标数字** |
| **来源** | `st.top()`，即**弹完之后幸存的那个**（不是被弹出的） |
| **空栈的含义** | **没有边界**（左边 / 右边没有任何柱子挡住我） |
| **空栈的写法** | 用**哨兵**表示"不存在"：左边界填 **`-1`**，右边界填 **`n`** |

```cpp
left[i]  = st.empty() ? -1 : st.top();      // 左边没有更矮的 → -1
right[i] = st.empty() ?  n : st.top();      // 右边没有更矮的 → n
```

**为什么哨兵恰好是 `-1` 和 `n`**：宽度公式是 `right[i] - left[i] - 1`，
它对应能延伸到的真实下标范围 `[left[i]+1, right[i]-1]`。
填 `-1` / `n` 之后公式自动退化出正确结果，**不需要任何特判**：

| 情形 | left | right | 宽度 | 含义 |
|---|---|---|---|---|
| 两边都有更矮的 | `1` | `4` | `4-1-1 = 2` | 只在 2~3 之间 |
| 左边没有 | `-1` | `4` | `4-(-1)-1 = 4` | 一直延伸到下标 0 |
| 右边没有 | `1` | `n` | `n-1-1` | 一直延伸到 `n-1` |
| 两边都没有（全局最矮） | `-1` | `n` | `n-(-1)-1 = n` | 整条数组 |

`[2,1,5,6,2,3]` 的 `i=1 (h=1)` 就是第 4 种：`left=-1, right=6` ⟹ 宽 `6`，面积 `1×6=6`
（`1` 是最矮的，除了它自己谁都挡不住它）。

> 所以**"栈空"不是异常，不是需要打补丁的边界情况 —— 它本身就是"没有边界"这个合法答案**。
> 这也正是为什么赋值必须写在 `while` 之后：只有循环结束，才知道该填 `st.top()` 还是该填哨兵。

## 1. 逻辑证明（不靠直觉也成立）

```cpp
while (!st.empty() && heights[st.top()] >= heights[i]) st.pop();
```

- 凡是被 `pop()` 掉的元素 `t`，都满足 `heights[t] >= heights[i]`（弹它的条件）；
- 而边界的定义是 `heights[boundary] < heights[i]`（必须严格更矮才算挡住我）。

两个集合**交集为空**。所以 `left[i] = st.top()` 写在 `while` 之内，
从条件写下那一刻起就注定是错的，换任何比较符号都救不回来。

---

## 2. 几何直觉

把矩形想成一块高度恰好 `heights[i]` 的方块，从 `i` 往两边推：

| 遇到的柱子 | 结果 |
|---|---|
| 比它**高** | 方块从它身上穿过去，**不挡路** |
| 比它**矮** | 撞墙，**必须停** |

被弹出来的正是"高柱子"——**恰恰是不挡路的那批**。
栈顶留下的那根，才是第一块挡路的墙。

---

## 3. 栈顶为什么是"最近"的

栈内**下标递增**、**高度递增**。弹完之后：

- 栈顶满足 `heights[st.top()] < heights[i]` → 它是墙；
- 同时它是栈中下标最大的 → 它是**最近的**那堵墙。

于是：`栈顶 = 唯一没被清掉的墙 = 最近的墙`。

---

## 4. 最容易踩的坑：栈上相邻 ≠ 数组相邻

一个很自然的想法：

> "最后被弹出的那个，不就是边界的前一个吗？记它不就行了？"

**在栈的意义上这是对的**——最后被弹出的确实是"边界在栈中的上邻"。
**但它不等于 `边界 + 1`。** 因为夹在中间的那些下标，早在**之前的轮次**就被弹掉了：
它们不在栈里，却实实在在还在数组中。

### 反例：`[1, 3, 2, 2]`，看 `i = 3`

处理到 `i = 3` 时，栈是 `[0(h=1), 2(h=2)]`：

```
top=2, h=2 <= h[3]=2  → 弹出   ← 最后被弹出的就是它，记下 2
top=0, h=1 <  h[3]=2  → 停住   ← 边界是 0
```

- 正确左端点 = `边界 + 1 = 1`（下标 1 高 3 ≥ 2，能盖住）
- 错误记法给出 **2**

原因：下标 1 在 `i = 2` 那轮就被弹掉了——当时 `h[2]=2 <= h[1]=3`。
它在数组里，但不在栈里。

```
栈里:   0 ── 2          （1 已经不在了）
数组:   0    1    2    3
              ↑          ← 存在于数组，消失于栈
```

### 深层原因

单调栈维护的是**左侧记录（left records）**：索引 1（高 3）被索引 2（高 2）取代，
因为"更矮且更靠右"对未来任何 `i` 都更有挡路能力，索引 1 永远不可能再当谁的边界了。

这个剪枝是单调栈 `O(n)` 的根源，但代价就是：**栈里只剩下一部分下标，位置信息被压缩了**。
所以绝不能用栈上的相对关系去推算数组下标。

### 危险之处

这种记法只会**偏大**（`p1 > 边界`）→ 宽度偏小 → **答案被低估，且不报错**，
很容易误以为通过了。

## 5. 还有一个致命点：循环体内部，边界"是否存在"是未知的

```cpp
while (!st.empty() && heights[st.top()] >= heights[i]) {
    left[i] = st.top();   // 此刻边界是谁？不知道
    st.pop();
}
```

`while` 可能把整个栈弹空——那就**根本没有边界**，端点应该是 `0`（边界语义下是 `-1`）。
"有没有边界"这个信息只有在循环结束的那一刻才确定。
所以"边界的前一个"这个概念，在循环体内部是**未定义**的。

---

## 6. 两套自洽语义（默认值 / 赋值位置 / 宽度公式，三处必须统一）

### A. 边界语义（推荐，语义最直接）

```cpp
// 左边界：从左往右扫
for (int i = 0; i < n; i++) {
    while (!st.empty() && heights[st.top()] >= heights[i]) st.pop();
    left[i] = st.empty() ? -1 : st.top();     // while 之外，主体是 i
    st.push(i);
}
// 右边界：从右往左扫（条件与上面完全对称）
for (int i = n - 1; i >= 0; i--) {
    while (!st.empty() && heights[st.top()] >= heights[i]) st.pop();
    right[i] = st.empty() ? n : st.top();
    st.push(i);
}
// 宽度
area = heights[i] * (right[i] - left[i] - 1);
```

### B. 端点语义（赋值确实在 while 内，但主体是**被弹出者**）

```cpp
// 从左往右扫时，弹出的 t 的右端点由 i 决定
while (!st.empty() && heights[st.top()] >= heights[i]) {
    right[st.top()] = i - 1;      // 我 i 才是它的右边界，不是反过来
    st.pop();
}
// 循环结束后，栈里剩下的右端点补 n-1
while (!st.empty()) { right[st.top()] = n - 1; st.pop(); }
// 宽度
area = heights[i] * (right[i] - left[i] + 1);
```

B 内层的逻辑是：
> "`t` 往右看，第一个比它矮的是 `i`，所以 `t` 的右端点最高只能到 `i-1`。"

**信息属于 `t`，不属于 `i`。** 写成 `right[i] = st.top()` 就是把主语写反了——
本该"我给别人当边界"，变成了"别人给我当边界"。

> 所以严格说不是"必须写在 while 外"，而是：
> **弹栈这一个动作产生的是"被弹出者的信息"。**
> - 想记成**边界** → 在 `while` **外**记给 `i`；
> - 想记成**端点** → 在 `while` **内**记给被弹出者。
> - **绝不能记成"当前元素的下标"。**

---

## 7. 自检不变量（打印 left/right 后逐条核对）

```
1. left[i] <= i <= right[i]                              // 下标自洽
2. heights[left[i]]  < heights[i]   （无边界则 left  = -1）
3. heights[right[i]] < heights[i]   （无边界则 right = n）
4. left[i]..i 之间没有比 heights[i] 更矮的；i..right[i] 之间同理
```

**第 4 条是"第一个 / 最近"的直接翻译。**
所有坑都来自同一个错误：**把"最远的那个"当成了"最近的那个"**。

---

## 8. 口诀

> **先弹完，再取栈顶；
> 弹出去的是路人，留下的是墙；
> 栈上相邻不是数组相邻。**

---

## 9. 最终正确解（LeetCode 84）

```cpp
class Solution {
public:
    int largestRectangleArea(vector<int>& heights) {
        int n = heights.size();
        if (n == 0) return 0;

        vector<int> right(n), left(n);
        stack<int> s, s1;

        for (int i = 0; i < n; i++) {                    // 左边界
            while (!s.empty() && heights[s.top()] >= heights[i]) s.pop();
            left[i] = s.empty() ? -1 : s.top();
            s.emplace(i);
        }
        for (int i = n - 1; i >= 0; i--) {               // 右边界
            while (!s1.empty() && heights[s1.top()] >= heights[i]) s1.pop();
            right[i] = s1.empty() ? n : s1.top();
            s1.emplace(i);
        }

        int ans = 0;
        for (int i = 0; i < n; i++) {
            ans = std::max(ans, heights[i] * (right[i] - left[i] - 1));
        }
        return ans;
    }
};
```

验证：`[2,1,5,6,2,3]` → `left = [-1,-1,1,2,1,4]`，`right = [1,6,4,4,6,6]`，
`i=2` 得 `5 × (4-1-1) = 10` ✓
`[2,2]` → 4 ✓
`[1,3,2,2]` → 6 ✓
