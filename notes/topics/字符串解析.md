# 字符串解析：从字符串里提取信息

> 一句话：**定位 → 切分 → 转换**。
> 永远不要写死下标（`s[8]`），永远不要 `(int)` 一个字符（那是 ASCII 码）。

> 触发这篇笔记的两个坑：LeetCode 150 的 `(int)tokens[i][0]`，
> 以及 LeetCode 636 的 `(int)logs[i][0]` + `logs[i][8]`（被 ASan 抓了个 `heap-buffer-overflow`）。

---

## 一、两次踩坑，同一个根因

| 题 | 我写的 | 实际拿到 | 表现 |
|---|---|---|---|
| LC 150 逆波兰 | `(int)tokens[i][0]` | `'2'` → **50** | 栈里全是 ASCII，`"23"`、`"-11"` 直接报废 |
| LC 636 独占时间 | `(int)logs[i][0]` | `'0'` → **48** | `root[48]` 越界 → **ASan: heap-buffer-overflow, READ of size 4** |
| LC 636 独占时间 | `(int)logs[i][8]` | `'0'` → 48；短串还越界 | 时间戳静默变成垃圾值 |

**根因**：把**字符串**当成**数组**用。字符串里的每个元素是**字符**，不是数字；
而且字段长度**不固定**（`n ≤ 100` → 编号可能是两位数；时间戳 ≤ 1e9 → 可能十位数），下标不可能写死。

## 二、三步套路

以 `s = "12:start:345"` 为例，我要拿到 `id = 12`、`type = start`、`t = 345`。

### 第 1 步：定位 —— `find`

```cpp
size_t p1 = s.find(':');           // 1   第一个冒号
size_t p2 = s.find(':', p1 + 1);   // 7   从 p1+1 开始找第二个冒号
// 找不到时返回 string::npos（不是 -1，也不是 0）
```

### 第 2 步：切分 —— `substr`

```cpp
s.substr(0, p1);        // "12"        [0, p1)
s.substr(p1 + 1, 5);    // "start"     ★ 第二个参数是"长度"，不是结束下标
s.substr(p2 + 1);       // "345"       省略长度 = 一直到末尾
```

### 第 3 步：转换 —— `stoi` / `stoll`

```cpp
int       id = stoi(s.substr(0, p1));     // 字符串 → int
long long t  = stoll(s.substr(p2 + 1));   // 大数用 stoll
bool isStart = (s.substr(p1 + 1, 5) == "start");
```

三行搞定，和字段多长、编号几位、时间戳几位**完全无关**。

## 三、四种写法对照（都正确，按场合选）

### 写法 1：`find` + `substr` + `stoi` ✅ 推荐

```cpp
size_t p1 = log.find(':');
size_t p2 = log.find(':', p1 + 1);
int  id      = stoi(log.substr(0, p1));
bool isStart = (log.compare(p1 + 1, 5, "start") == 0);
long long t  = stoll(log.substr(p2 + 1));
```

通用、无依赖、切任意字段都行。**优先用这个。**

### 写法 2：`stringstream` + `getline(ss, token, ':')` ✅ 切分最省心

```cpp
stringstream ss(log);
string sId, sType, sTime;
getline(ss, sId,   ':');
getline(ss, sType, ':');
getline(ss, sTime);          // 最后一段到末尾
int  id      = stoi(sId);
bool isStart = (sType == "start");
long long t  = stoll(sTime);
```

字段一多（比如 CSV）就显出优势，不用自己算下标。缺点：比写法 1 慢一点。

### 写法 3：`sscanf`（C 风格，最短）

```cpp
int id = 0; char type[16] = {0}; long long t = 0;
sscanf(log.c_str(), "%d:%15[^:]:%lld", &id, type, &t);
```

`%15[^:]` = "最多 15 个非 `:` 字符"。要记得 `c_str()`、缓冲区大小、以及 `%lld` 对应 `long long`。
MSVC 下需要 `#define _CRT_SECURE_NO_WARNINGS`。

### 写法 4：手写扫描（零分配、最快，面试可讲原理）

```cpp
int id = 0;
while (i < s.size() && isdigit((unsigned char)s[i]))
    id = id * 10 + (s[i++] - '0');       // ★ 关键：c - '0'
```

这就是 `stoi` 内部干的事。理解它，才能真正理解"字符 → 数字"。

### 对比表

| 写法 | 代码量 | 速度 | 依赖 | 适合 |
|---|---|---|---|---|
| `find` + `substr` + `stoi` | 中 | 快 | 无 | **默认首选** |
| `stringstream` + `getline` | 中 | 较慢 | `<sstream>` | 字段多、格式松散 |
| `sscanf` | 短 | 快 | `<cstdio>` | 格式严格固定 |
| 手写扫描 | 长 | 最快 | 无 | 竞赛、性能敏感 |

## 四、`char` ≠ 数字：唯一的桥是 `c - '0'`

| 字符 | ASCII |
|---|---|
| `'0'` | 48 |
| `'7'` | 55 |
| `'9'` | 57 |
| `':'` | 58 |

- `(int)'7'` → **55**（这是 ASCII 码，不是 7）
- `'7' - '0'` → **7** ✅

因为 `'0' ~ '9'` 在 ASCII 里是**连续的**，所以"字符数字 → 数值"就是减去 `'0'` 的码值。
顺带一个漂亮的巧合：`':'` 正好是 58，紧挨着 `'9'`，所以 `c <= '9'` 就能判断"是不是数字字符"。

### ⚠️ `c - '0'` 只能处理**一位数**

```cpp
"12" → s[0] - '0' == 1     // 只拿到 1，两位数的 2 丢在哪了？
```

本题 `n ≤ 100`，函数编号可能是 `11`；时间戳最大 1e9，是十位数。
**所以单字符转换在这里根本不够用**，必须整段 `stoi` / `stoll`。

> 什么时候能用 `c - '0'`？明确知道"这一段就是 1 个字符"的时候（比如棋盘的 `'3'`、单个数字）。

## 五、四个必背的细节坑

### ❌ 坑 1：`substr` 的第二个参数是**长度**，不是结束下标

```cpp
s = "0:start:123";
s.substr(8, 2);    // "12"      下标 8 开始，取 2 个
s.substr(8);       // "123"     省略 = 到末尾
s.substr(8, 99);   // "123"     超长不报错，自动截断到末尾
s.substr(99);      // ❌ 抛 std::out_of_range（起点就越界）
```

### ❌ 坑 2：`find` 找不到返回 `npos`

```cpp
if (s.find('@') == string::npos) { /* 没找到 */ }
```

`npos` 是 `size_t` 的全 1（极大值），**不能**写 `== -1`（虽然能隐式转换，可读性差），
更不能写 `if (s.find('@'))`（返回 0 也代表"找到了，在下标 0"，会被误判成没找到）。

### ❌ 坑 3：`stoi` 只解析**前缀**，且不报错

```cpp
stoi("123abc")      // 123   ← 后面的 "abc" 被无视，不抛异常！
```

想确认"整串都是数字"，用 `pos` 传出参数：

```cpp
size_t pos = 0;
int v = stoi(s, &pos);
if (pos != s.size()) { /* 后面还有杂质 */ }
```

### ❌ 坑 4：`stoi` 会抛异常（不是返回 0）

| 异常 | 触发 | 例子 |
|---|---|---|
| `std::invalid_argument` | 一个字符都解析不了 | `stoi("abc")`、`stoi("")` |
| `std::out_of_range` | 超出 `int` 范围 | `stoi("99999999999")` |

判题输入合法时不必包 try/catch；生产代码要包。
**时间戳这种"题目说到 1e9"的字段，直接用 `stoll` 更省心。**

### 补充：C++17 的 `from_chars`（不抛异常、最快）

```cpp
#include <charconv>
int v = 0;
auto [ptr, ec] = std::from_chars(s.data(), s.data() + s.size(), v);
if (ec == std::errc{}) { /* 成功，ptr 指向第一个没解析的字符 */ }
```

不分配、不抛异常、能通过 `ec` / `ptr` 精确判断错误。整数版 GCC 8+ 就有，浮点版要 GCC 11+。

## 六、回到 LC 636：解析只要 4 行

```cpp
Log parseLog(const string& log) {
    size_t p1 = log.find(':');
    size_t p2 = log.find(':', p1 + 1);
    Log e;
    e.id      = stoi(log.substr(0, p1));
    e.isStart = (log.compare(p1 + 1, 5, "start") == 0);
    e.t       = stoll(log.substr(p2 + 1));
    return e;
}
```

`compare(p1 + 1, 5, "start")`：从下标 `p1+1` 起取 5 个字符和 `"start"` 比，相等返回 0。
`end` 只有 3 个字符，长度不同必然不等 —— 比 `substr(...) == "start"` 少一次临时字符串构造。
更直白的写法也可以：

```cpp
e.isStart = (log[p1 + 1] == 's');     // "start"/"end" 首字母不同，一个字就够
```

> 但要注意 `log[p1 + 1]` 是**定位出来的**下标（来自 `find`），不是写死的魔法数字 —— 这才是关键区别。

## 七、顺手的两个通用工具

### 按分隔符切分

```cpp
vector<string> split(const string& s, char delim) {
    vector<string> out;
    string cur;
    for (char c : s) {
        if (c == delim) { out.push_back(cur); cur.clear(); }
        else            { cur += c; }
    }
    out.push_back(cur);          // 别忘了最后一段
    return out;
}
```

> `split` 出来的是**字符串**，还要 `stoi`；别指望它直接给你数字。

### 按行读（读文件/多行输入）

```cpp
string line;
while (getline(cin, line)) { ... }        // 注意：getline 不读行尾的 '\n'
```

### 去掉首尾空白

```cpp
size_t b = s.find_first_not_of(" \t\r\n");
size_t e = s.find_last_not_of(" \t\r\n");
string t = (b == string::npos) ? "" : s.substr(b, e - b + 1);
```

## 八、一句话记忆

> **字符串是"字符的序列"，不是"数字的序列"。**
> 想拿到里面的数字，必须先**定位**它的边界（`find`），再**切出**这一段（`substr`），最后**整段转换**（`stoi` / `stoll`）。
> `c - '0'` 只解决"**一个**数字字符"；`(int)c` 拿到的永远是 ASCII 码，什么也解决不了。
> **写死下标 = 定时炸弹**：换一组数据（两位数编号、更长的时间戳）就炸，而且常常是静默算错。
