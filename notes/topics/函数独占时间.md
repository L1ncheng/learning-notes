# 函数的独占时间（Exclusive Time of Functions）

> 一句话：**单线程 CPU 的执行过程就是一棵调用树**。用一个栈模拟这棵树，
> 栈顶的那个函数"吃掉"两条日志之间的时间片——**start 吃 `[prev, t-1]`，end 吃 `[prev, t]`（含 t 这个点！）**。

> 对应题目：LeetCode 636. Exclusive Time of Functions（中等）
> 配套可运行代码：`exclusive_time.cpp`（三种实现 + 随机对拍）

---

## 一、题目在问什么

给 `n` 个函数（编号 `0 ~ n-1`）、一串日志 `"id:start|end:timestamp"`。
日志按时间递增给出，规则：

- `start`：把 id **压栈**，表示它开始执行；
- `end`：把 id **弹栈**，表示它结束执行；
- 栈顶永远是**当前正在执行的函数**（单线程，任何时刻只有一个函数在跑）。

要求：**每个函数自己真正执行了多少个时间单位**（调用别人花的时间不算我的）。

两个关键保证：

| 保证 | 含义 |
|---|---|
| 单线程 | 时间轴可以被**无重叠地切分**，每个时刻只属于一个函数 |
| 有 start 必有 end | 栈最终一定弹空，每个时间片都能落实到一个函数头上 |

---

## 二、本题最大的坑：时间戳的两个语义

| 日志 | 语义 | 它占不占这个时间点？ |
|---|---|---|
| `0:start:2` | 在时间戳 **2 的起始**开始执行 | ✅ 占（2 属于函数 0） |
| `0:end:5` | 在时间戳 **5 的末尾**结束执行 | ✅ **也占**（5 仍属于函数 0） |

**start 和 end 指向的时刻都属于这个函数**，只有「函数之间的空隙」不属于任何人。

示例 1 的时间轴（`n=2, logs=["0:start:0","1:start:2","1:end:5","0:end:6"]`）：

```
时刻 t :   0   1   2   3   4   5   6
执行者 :   0   0   1   1   1   1   0
           └─ 2 秒 ─┘ └─── 4 秒 ───┘ └1秒┘
```

- 函数 0：时刻 0、1 → 2 个单位；时刻 6 → 1 个单位，合计 **3**
- 函数 1：时刻 2、3、4、5 → **4**

答案 `[3, 4]`。

> ⚠️ 所以：
> - **start 事件不要 +1**：它和第 2 个函数的开始之间是"左闭右开"的 `[prev, t-1]`；
> - **end 事件必须 +1**：`[prev, t]` 两端都归它。
> 这个 `+1` 忘了，示例 1 就会算成 `[2, 3]`。

## 三、核心思路：prev 记账法

不去管"函数是什么"，只维护一个变量：

> `prev` = **上一次时间轴发生变化的时刻**（也就是"从这一刻起，栈顶换了人"）。
> 那么每一段 `[prev, ...]` 的时间，永远归**当前栈顶**。

遍历日志，两条规则：

| 事件 | 做什么 | 为什么 |
|---|---|---|
| `id:start:t` | ① 若栈非空，`res[栈顶] += t - prev`（半开区间 `[prev, t-1]`，共 `t - prev` 个单位）<br>② `push(id)`；`prev = t` | 新函数从 t 才开始跑，所以 t 之前（不含 t）还是老栈顶在跑 |
| `id:end:t` | ① `res[栈顶] += t - prev + 1`（闭区间 `[prev, t]`，共 `t - prev + 1` 个单位）<br>② `pop()`；`prev = t + 1` | end 的时刻 t 仍属于它；父函数要等到 **t+1** 才恢复执行 |

> `prev = t + 1` 是灵魂：**t 这一刻已经被弹出去的那个函数占用了**，父函数必须从下一时刻重新开始计时。

### 示例 3 逐条走一遍

`n = 2, logs = ["0:start:0","0:start:2","0:end:5","1:start:6","1:end:6","0:end:7"]`

| 日志 | 给谁结算 | res（函数0, 函数1） | prev | 栈（底→顶） |
|---|---|---|---|---|
| `0:start:0` | 栈空，不结算 | `[0, 0]` | 0 | `[0]` |
| `0:start:2` | res[0] += `2-0` = 2 | `[2, 0]` | 2 | `[0, 0]`（递归） |
| `0:end:5` | res[0] += `5-2+1` = 4 | `[6, 0]` | **6** | `[0]` |
| `1:start:6` | res[0] += `6-6` = 0 | `[6, 0]` | 6 | `[0, 1]` |
| `1:end:6` | res[1] += `6-6+1` = 1 | `[6, 1]` | **7** | `[0]` |
| `0:end:7` | res[0] += `7-7+1` = 1 | `[7, 1]` | 8 | `[]` |

答案 `[7, 1]` ✅

注意第 4 行：因为上一条 `end` 把 `prev` 推到了 **6**，函数 1 恰好在 6 开始，所以补给函数 0 的正好是 **0 秒**——完全正确，函数 0 在时刻 5 末尾就交出了 CPU。

## 四、C++ 实现（方案一，推荐）

```cpp
class Solution {
public:
    vector<int> exclusiveTime(int n, vector<string>& logs) {
        vector<int> res(n, 0);
        vector<int> st;          // 栈里只存函数 id
        long long prev = 0;      // 上一次"状态切换"的时刻

        for (const string& log : logs) {
            // 解析 "id:start|end:timestamp"
            size_t p1 = log.find(':');
            size_t p2 = log.find(':', p1 + 1);
            int  id      = stoi(log.substr(0, p1));
            bool isStart = (log.compare(p1 + 1, 5, "start") == 0);
            long long t  = stoll(log.substr(p2 + 1));

            if (isStart) {
                if (!st.empty()) res[st.back()] += (int)(t - prev);   // [prev, t-1]
                st.push_back(id);
                prev = t;
            } else {
                res[st.back()] += (int)(t - prev + 1);                // [prev, t]
                st.pop_back();
                prev = t + 1;                                         // 父函数从 t+1 恢复
            }
        }
        return res;
    }
};
```

> `stoll` 只是习惯性稳一手（时间戳最大 1e9，`int` 够用）。
> **结果本身也不会溢出**：一个函数的总独占时间 ≤ 总时间跨度 ≤ 1e9 + 1 < 2^31-1。

## 五、另一种写法（方案二）：栈帧自带开始时刻

不让 `prev` 记账，而是**每个栈帧自己记住"我这次是从哪一刻开始跑的"**：

```cpp
vector<int> exclusiveTime2(int n, vector<string>& logs) {
    vector<int> res(n, 0);
    vector<int> st;
    vector<long long> startAt;      // 与 st 同步

    for (/* 每条日志，解析出 id / isStart / t */) {
        if (isStart) {
            if (!st.empty()) res[st.back()] += (int)(t - startAt.back());  // 父函数跑到 t-1
            st.push_back(id);
            startAt.push_back(t);
        } else {
            res[id] += (int)(t - startAt.back() + 1);   // 含 t
            st.pop_back();
            startAt.pop_back();
            if (!st.empty()) startAt.back() = t + 1;    // 父函数从 t+1 继续，重新计时
        }
    }
    return res;
}
```

两种方案的对照：

| | 方案一 `prev` 记账 | 方案二 栈帧记开始时刻 |
|---|---|---|
| 栈里存什么 | 只存 id | id + 开始时刻（两个同步的栈，或 `pair`） |
| 变量 | 一个全局 `prev` | 每个栈帧一个 `startAt` |
| 关键动作 | end 后 `prev = t + 1` | end 后 `startAt.back() = t + 1` |
| 代码量 | 更短 ✅ | 稍长 |
| 直观性 | "时间片归栈顶" | "我这个栈帧跑了多久" |

**两者本质完全一样**：方案二的 `startAt.back()` 就是方案一的 `prev`。会一个即可。

## 六、暴力对拍（方案三，验证用）

最朴素的定义法：**对每个整数时刻 t，看谁在栈顶，就给它 +1**。

```cpp
// 逐单位模拟（时间戳小的时候才能用）
for (long long t = 0; t <= maxT; ++t) {
    // 同一时刻的 start 先处理（它在 t 这一秒开始执行）
    while (j < ev.size() && ev[j].t == t && ev[j].isStart) { st.push_back(ev[j].id); ++j; }
    if (!st.empty()) res[st.back()] += 1;        // t 这一秒归栈顶
    // 同一时刻的 end 后处理（它在 t 这一秒的末尾才结束）
    while (j < ev.size() && ev[j].t == t && !ev[j].isStart) { st.pop_back(); ++j; }
}
```

在 `exclusive_time.cpp` 里我用它和方案一/方案二/方案三做了 **3000 组随机对拍**（随机生成合法的嵌套/递归日志），四种实现结果完全一致——
这就是「`end` 要 `+1`、`prev` 要 `t+1`」这两条规则最硬的证据。

## 七、常见错误清单（按踩坑频率排序）

### ❌ 错误 1：`end` 忘了 `+1`

```cpp
res[st.back()] += t - prev;      // ❌ end 的 t 这一刻丢了
```

示例 1 会得 `[2, 3]`（正确 `[3, 4]`），示例 2、3 同样整体偏小。

**修复**：`end` 是闭区间，`t - prev + 1`。

### ❌ 错误 2：`end` 之后 `prev = t`（写成 t 而不是 t+1）

```cpp
st.pop_back();
prev = t;                        // ❌ 时刻 t 被算了两次
```

示例 1 会得 `[4, 4]`（函数 0 多算了 1 秒）。

**修复**：`prev = t + 1`。

### ❌ 错误 3：`start` 时先 `push` 再结算

```cpp
st.push_back(id);
res[st.back()] += t - prev;      // ❌ 新函数把"还没出生"的时间也算成自己的了
```

示例 1 会得 `[1, 6]`（正确 `[3, 4]`），错得最离谱。

**修复**：**先结算老栈顶，再 push，最后 `prev = t`**。

### ❌ 错误 4：以为 start 也要 +1

半开区间 `[prev, t-1]` 是 `t - prev`，不是 `t - prev + 1`。
记忆法：**"开始"是抢班，"结束"是交班**——交班的人要把最后一秒干完。

### ❌ 错误 5：把 `prev` 初始化成第一条日志的时间戳以外的东西

`prev` 只影响第一次结算，而第一次一定是 `start` 且栈空（不结算），所以 `prev = 0` 是安全的。
但如果你写成"遍历时才开始维护"，务必保证它是 `long long` 并且从第一条日志的语义出发理解。

### ❌ 错误 6：空栈弹栈 / 空栈结算

合法输入下，第一条日志必然是 `start`，所以 `res[st.back()]` 不会在空栈上执行。
但生产代码建议加防御（和《逆波兰表达式》那题同样的教训）：

```cpp
if (st.empty()) { /* 数据非法，跳过或报错 */ continue; }
```

### ❌ 错误 7：试图给 `logs` 排序 / 用字符串比较处理时间戳

题目保证日志按时间递增；时间戳是数字，字符串比较 `"10" < "9"` 是错的。
要解析就 `stoll`，别拿字符串当数字比。

### ❌ 错误 8：用布尔数组记录"函数在不在运行"

**递归调用同一个函数**时（示例 2：`0` 调用 `0` 再调用 `0`），
"在不在运行"无法区分三层嵌套，也分不清 `end` 该给哪一层结算。
必须用**栈**（每个 `start` 是一个独立栈帧）。

## 八、Python 参考实现

```python
def exclusive_time(n, logs):
    res = [0] * n
    st = []
    prev = 0
    for log in logs:
        fid, typ, t = log.split(':')
        fid, t = int(fid), int(t)
        if typ == 'start':
            if st:
                res[st[-1]] += t - prev          # [prev, t-1]
            st.append(fid)
            prev = t
        else:
            res[st[-1]] += t - prev + 1          # [prev, t] 含 t
            st.pop()
            prev = t + 1                         # 父函数从 t+1 恢复
    return res
```

## 九、复杂度

| 项 | 复杂度 | 说明 |
|---|---|---|
| 时间 | **O(L)**，L = `logs.length` | 每条日志 O(1)（解析、一次加法、一次压/弹栈） |
| 空间 | **O(n + S)**，S = 最大栈深 | `res` 数组 O(n)，调用栈最深 O(S)，S ≤ L |

数据规模 n ≤ 100、L ≤ 500，随便过。

## 十、一句话记忆

> **单线程 = 时间轴可以被一个栈无重叠地切开。**
> 每个 `start` 和 `end` 都是一个"切点"：`start` 前的时间归**老栈顶**（半开，不加 1），
> `end` 包含自己那一刻（闭区间，**加 1**），并且**父函数从 `t+1` 才恢复**。
> 递归调用靠栈的"一层一个栈帧"自然处理——**不要用布尔数组**。

| | 逆波兰求值（LC 150） | 函数的独占时间（LC 636） |

## 十四、代码批改：`root` / `time` 双数组写法

### 我提交的版本

```cpp
class Solution {
public:
    vector<int> exclusiveTime(int n, vector<string>& logs) {
        vector<int>root(n,0);  //记录起始
        vector<int>time(n,0);//记录时间
        vector <int>stack;
        int size=logs.size();
        stack.push_back((int)logs[0][0]);
        for(int i=1;i<size;i++)
        {
            int x=(int)logs[i][0]; //编号
            int t=(int)logs[i][8]; //时间点
            char pd=logs[i][2];
            int top=stack.back();
            if(pd=='s')
            {
                time[top]+=(t-root[top]+1);
                root[x]=t;
                stack.push_back(x);
            }
            else
            {
                time[x]+=(t-root[top]+1);
                stack.pop_back();
                if(stack.size())
                {
                    root[stack.back()]=t+1;
                }
            }
        }
        return  time;
    }
};
```

### 结论：**思路是对的，四个细节全错**

"每个栈帧记一个开始时刻、end 时结算、弹栈后把父函数的开始时刻改成 `t+1`" ——
这套想法**完全正确**，就是上面的方案二 / 方案三（`exclusive_time.cpp` 里的 `exclusiveTime3`）。
错的是解析和一处 `+1`。

### 逐条诊断

| # | 位置 | 问题 | 后果 |
|---|---|---|---|
| 1 | `(int)logs[i][0]` | 拿到的是**字符的 ASCII 码**，不是函数编号 | `'0'` → `48`，于是 `stack` 里存的是 48；紧接着 `time[top]` = `time[48]`，`n=2` 时**直接越界写堆内存**（UB，ASan 会报 `heap-buffer-overflow`） |
| 2 | `(int)logs[i][8]` | 时间戳**下标被写死成 8** | 只有 `"0:start:0"` 这种恰好 9 字符的串才碰巧对，而且读到的还是 `'0'`=48；`"1:end:5"` 只有 7 个字符，`logs[i][8]` 已经**越过字符串末尾**（`pos > size()` 是 UB）；时间戳到 1e9 有 10 位，更不可能对 |
| 3 | `logs[i][2]` | 类型字段下标被写死成 2 | 函数编号 ≥ 10 时（n ≤ 100，是合法的）`"12:start:0"` 的下标 2 是 `':'`，会被当成 `end` 分支 |
| 4 | `time[top]+=(t-root[top]+1)` | **start 事件多加了 1** | `start` 是半开区间 `[root, t-1]`，长度 `t - root`。见第七节"错误 4"：*开始是抢班，结束是交班* |
| 5 | `stack.push_back((int)logs[0][0]);` 且循环从 `i=1` 开始 | 第一条日志被特殊对待，靠 `root` 初值 0 蒙对 | 首条日志时间戳不是 0 时答案就错（如 `["0:start:5","0:end:9"]` 会算成 10） |
| 6 | 变量名 `stack` / `size` | 遮蔽 `std::stack`、`std::size` | 本题不报错，但是隐患，换题容易炸 |

把解析换成正确写法、去掉那个 `+1` 后，实测（Python 等价实现）：

| 版本 | 示例 1 | 示例 2 | 示例 3 |
|---|---|---|---|
| 原版公式（只把解析换成正确写法） | `[4,4]` ✗ | `[10]` ✗ | `[9,1]` ✗ |
| 解析 + 去掉 start 的 `+1` | `[3,4]` ✓ | `[8]` ✓ | `[7,1]` ✓ |

> 注意：**只修 `+1` 是错误的做法**——示例 2 少加的 2 秒来自两个 start 事件，示例 3 也是 2 个 start 事件，
> 恰好都是"多算一次 1 秒"。所以这个 `+1` 必须去掉，而不是"有时候去掉有时候不去掉"。

### 改好的版本（保留我的 `root` / `time` 双数组结构）

```cpp
class Solution {
public:
    vector<int> exclusiveTime(int n, vector<string>& logs) {
        vector<int> res(n, 0);
        vector<int> root(n, 0);    // root[id] = id 当前最内层栈帧的开始时刻
        vector<int> st;            // 栈里只存函数 id

        for (const string& log : logs) {
            size_t p1 = log.find(':');            // id 后面
            size_t p2 = log.find(':', p1 + 1);    // start/end 后面
            int id       = stoi(log.substr(0, p1));
            bool isStart = (log[p1 + 1] == 's');
            long long t  = stoll(log.substr(p2 + 1));

            if (isStart) {
                if (!st.empty()) res[st.back()] += (int)(t - root[st.back()]);  // 半开，无 +1
                st.push_back(id);
                root[id] = (int)t;
            } else {
                res[id] += (int)(t - root[id] + 1);              // 闭区间，含 t
                st.pop_back();
                if (!st.empty()) root[st.back()] = (int)t + 1;    // 父函数从 t+1 恢复
            }
        }
        return res;
    }
};
```

### 为什么 `root` 用"函数 id 下标"而不是"栈帧"也不出错？（递归的关键）

我一开始担心：递归时 `root[id]` 会被内层覆盖，外层的开始时刻不就丢了？

**不会**，因为程序永远只需要"**这个 id 当前最内层那一帧**"的开始时刻：

| 事件 | `root[id]` 的变化 | 为什么够用 |
|---|---|---|
| 内层 `start` | 被覆盖成内层的 `t` | 外层此刻暂停，它的开始时刻暂时**不需要**（它已经被结算过了） |
| 内层 `end` | 结算完内层后，写成 `t+1` | 这正是外层"恢复执行"的时刻，等于把外层的信息**还回来了** |

所以一个长度为 `n` 的数组就够，不需要和栈一起压/弹。这一点在 `exclusive_time.cpp` 的
`exclusiveTime3()` 里有对应代码，并和 `prev` 版、栈帧版、暴力版做了随机对拍（0 处不一致）。

### 第二轮：改用 `sscanf` 之后的新坑

```cpp
int x; char pd[16] = {0}; long long t;
sscanf(logs[i].c_str(), "%d:%15[^:]:%lld", &x, pd, &t);   // 解析对了 ✅
int top=stack.back();          // ← ASan 报的 16:27 就是这里（空栈取栈顶）
if(pd=="start")                // ← 真正的元凶：数组名 vs 字符串字面量，比的是地址
```

| # | 问题 | 机制 | 后果 |
|---|---|---|---|
| 1 | `pd == "start"` | `pd` 是 `char[16]`，**退化成指针**；`"start"` 也是地址。比的是两个地址，**永远 false**（GCC 只给一条 `-Waddress` 警告，编译照样通过） | 每条日志都被当成 `end` → 每条都 `pop_back()` → 栈被抽干 |
| 2 | `int top=stack.back();` 写在 `if` **外面** | `start` 时栈**可以合法为空**（一个新的顶层函数开始执行时，栈里本来就没有父函数） | 空栈 `back()` = 读 `data[-1]` → **heap-buffer-overflow, READ of size 4** |
| 3 | `start` 分支仍带 `+1` | 半开 / 闭区间搞混 | 不崩，但 WA |

实测（Python 等价模拟，题目给的三个示例）：

| 版本 | 示例 1 | 示例 2 | 示例 3 |
|---|---|---|---|
| 就是上面这份（`pd=="start"` 恒假） | **崩在 `logs[2]`** | 崩在 `logs[2]` | 崩在 `logs[2]` |
| 只把 `pd=="start"` 改成 `strcmp` | `[4,4]` ✗ | `[10]` ✗ | `[9,1]` ✗ |
| 再删掉 `start` 的 `+1` | `[3,4]` ✓ | `[8]` ✓ | `[7,1]` ✓ |

### 怎么读 ASan 这份报告（三个关键）

1. **`solution.cpp:16:27` = 第 16 行第 27 列**。12 个空格缩进时，
   `            int top=stack.back();` 的第 27 列正好是 `back` —— 是 `.back()` 这个调用，不是下标越界。
2. **`READ of size 4`** = 正在读一个 `int` → 崩在某个 `vector<int>` 上（`root` / `time` / `stack`）。
3. 报告**尾部**那行 `0x... is located N bytes before/after N-byte region ... allocated by ... std::vector<int>`
   —— **字节数直接告诉你崩的是哪个 vector**：这里是 4 字节 = **1 个 int**，正是只 `push` 过一次、
   又被 `pop` 空了的 `stack`（容量 1 的缓冲区，`back()` 去读 `data[-1]`）。

> 教训：**编译通过 ≠ 语义正确**。`pd == "start"` 只是警告不是错误，
> 于是"错误分支"被悄悄执行，最后以越界崩溃的形式暴露 —— 和《逆波兰表达式》那次
> 「错误代码路径被歪打正着掩盖」是同一类问题。
