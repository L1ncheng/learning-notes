### 主题一：逆波兰表达式（Reverse Polish Notation）

- **是什么**：逆波兰表达式就是**后缀表达式**——运算符写在它的两个操作数**后面**。
  - 中缀：`(1 + 2) * (3 - 4)`
  - 前缀（波兰式）：`* + 1 2 - 3 4`
  - **后缀（逆波兰式）：`1 2 + 3 4 - *`**
- **为什么**：中缀依赖**括号**和**优先级**两样东西来决定计算顺序，计算机解析起来成本高。后缀表达式：
  1. **不需要括号**，运算顺序唯一确定；
  2. 没有优先级歧义，从左到右扫一遍就能算完；
  3. 只需要**一个栈**，实现极简。
  这也是 JVM 字节码、PostScript、Forth 语言的基础。
- **怎么用（求值算法，两条铁律）**：
  1. 遇到**操作数** → 压栈；
  2. 遇到**运算符** → **弹出 2 个、算成 1 个、压回去**。

  以 `1 2 + 3 4 - *` 为例：

  | 读入 | 操作 | 栈 |
  | :--- | :--- | :--- |
  | `1` | push | `[1]` |
  | `2` | push | `[1, 2]` |
  | `+` | 弹 2、1 → 1+2=3 → push | `[3]` |
  | `3` | push | `[3, 3]` |
  | `4` | push | `[3, 3, 4]` |
  | `-` | 弹 4、3 → 3-4=-1 → push | `[3, -1]` |
  | `*` | 弹 -1、3 → 3×(-1)=-3 → push | `[-3]` |

  结果 `-3` ✅

- **和已知知识的联系**：这就是「栈」这个数据结构最经典的应用场景——**后进先出**决定了运算符总是先和最靠近它的两个操作数结合。
  中缀是「人和数学的写法」，后缀是「机器和栈的写法」。

### 主题二：左右操作数的顺序（细节但致命）

先弹出的是**右操作数**，后弹出的是**左操作数**：

```
        栈顶
         ↓
   [ ... , 左, 右 ]
            ↑    ↑
         后弹出  先弹出
```

| 运算符 | 正确写法 | 说明 |
| :--- | :--- | :--- |
| `+` `*` | `左 + 右` / `左 * 右` | 顺序无所谓 |
| `-` `/` | `左 - 右` / `左 / 右` | **写反就 WA** |

注意 C++ 整数除法是**向零截断**：`-7 / 2 == -3`（不是 -4）。

### 主题三：`stoi` —— 字符串转数字

- **是什么**：`stoi` = **string to int**，解析**整个字符串**，支持正负号和多位数。
- **为什么需要**：我一开始用 `(int)tokens[i][0]` 把字符强转成 int，拿到的是 **ASCII 码**，完全不是数字。
- **怎么用**：

  ```cpp
  #include <string>   // stoi 在 <string> 里，不是 <cstdlib>

  stoi("123")     // 123
  stoi("-11")     // -11      支持负号
  stoi("+42")     // 42       支持正号
  stoi("  7")     // 7        跳过前导空白
  stoi("12abc")   // 12       解析到非法字符为止，不报错（危险！）
  ```

  **完整签名**：`int stoi(const string& str, size_t* pos = nullptr, int base = 10);`
  - `pos`：传出参数，返回第一个未解析字符的下标
  - `base`：进制，默认 10

  **异常（必须知道）**：`stoi` 遇到无法解析的内容会**抛异常**，不是返回 0。

  | 异常 | 触发条件 | 例子 |
  | :--- | :--- | :--- |
  | `std::invalid_argument` | 一个字符都解析不了 | `stoi("abc")`、`stoi("")` |
  | `std::out_of_range` | 超出 `int` 范围 | `stoi("99999999999")` |

- **和已知知识的联系**：`s[i] - '0'` 才是「字符数字 → 数值」的正确做法（`'0'` 的 ASCII 是 48）。
  直接 `(int)s[i]` 拿到的是 ASCII 码，这是今天最大的坑。
  家族成员：`stoi`(int) → `stol`(long) → `stoll`(long long) → `stod`(double)。

## 💻 代码与实践

### 最终通过的版本（LeetCode 150）

```cpp
class Solution {
public:
    int evalRPN(vector<string>& tokens) {
        vector<int> a;
        for (int i = 0; i < tokens.size(); i++) {
            char x = tokens[i][0];
            switch (x) {
                case '+': {
                    int t1 = a.back(); a.pop_back();
                    int t2 = a.back(); a.pop_back();   // ← 这一句曾经漏掉
                    a.push_back(t1 + t2);
                    break;
                }
                case '-': {
                    int t1 = a.back(); a.pop_back();
                    int t2 = a.back(); a.pop_back();   // ← 这一句曾经漏掉
                    a.push_back(t2 - t1);              // 注意 t2 - t1，别写反
                    break;
                }
                case '*': {
                    int t1 = a.back(); a.pop_back();
                    int t2 = a.back(); a.pop_back();   // ← 这一句曾经漏掉
                    a.push_back(t1 * t2);
                    break;
                }
                case '/': {
                    int t1 = a.back(); a.pop_back();
                    int t2 = a.back(); a.pop_back();   // ← 这一句曾经漏掉
                    a.push_back(t2 / t1);
                    break;
                }
                default:
                    a.push_back(stoi(tokens[i]));      // ← 曾经写成 (int)tokens[i][0]
            }
        }
        return a.back();
    }
};
```

### 最稳的 token 判断写法

```cpp
// 关键：t.size() == 1 锁定「运算符一定是单字符」
// 这样 t[0] 和 t.back() 完全等价，且能排除 "-11" 这类负数 token
for (const string& t : tokens) {
    if (t.size() == 1 && (t[0] == '+' || t[0] == '-' || t[0] == '*' || t[0] == '/')) {
        // t 是运算符
    } else {
        a.push_back(stoi(t));   // 其余一律当操作数
    }
}
```

### vector 当栈的对照表

| 栈操作 | vector 写法 |
| :--- | :--- |
| `push(x)` | `a.push_back(x)` |
| `top()` | `a.back()` |
| `pop()` | `a.pop_back()` |

> `vector` **没有** `pop()` 也没有 `push()`；`pop_back()` 返回值是 `void`，取栈顶必须先 `back()`。

## 🔍 难点与解决

| 问题 | 原因 | 解决办法 |
| :--- | :--- | :--- |
| `switch(x)` 报错：statement requires expression of integer type | `x` 是 `std::string`，`switch` 只接受整型 | 改成 `tokens[i][0]` 或 `tokens[i].back()` |
| 编译报「跨过初始化」 | `switch` 的所有 `case` **共用一个作用域**，变量声明处到块末尾都可见，跨标签跳转非法 | 每个 `case` 用 `{ }` 包起来 |
| 减法/除法结果错 | `-`、`*`、`/` 分支只弹了右操作数，**左操作数没 pop**，栈被污染；算完元素数不减反增 | `int t2 = a.back();` 后补 `a.pop_back();` |
| 数字压进栈变成 50、49 这种怪值 | `(int)tokens[i][0]` 拿到的是**字符的 ASCII 码**（`'2'` = 50），且多位数 `"23"` 只取到 `'2'`、负数 `"-11"` 只取到 `'-'` | 改用 `stoi(tokens[i])` |
| `[exit code]` 之前先出现 `AddressSanitizer: heap-buffer-overflow`，READ of size 4，地址在 `16-byte region` **前 4 字节** | `a.back()` 在**空 vector** 上被调用 = 读 `begin() - 1`，`int` 正好 4 字节 | 加 `a.size() < 2` 防护；根因是 token 被误判成运算符 |
| `char x = tokens[i][0]` 判成减号导致负数崩栈 | `"-11"` 的**首字符是 `-`**，被误当成减法运算符，去弹一个不存在的操作数 | 改用 `tokens[i].back()`，负数末字符一定是数字；更稳的是 `t.size() == 1 && 白名单` |

## ✅ 今日总结

- **逆波兰表达式求值只有两条铁律**：操作数压栈；运算符弹出两个、归约成一个。我两次踩坑都是违反了这两条（归约只做了一半、压进去的不是操作数）。
- **弹栈顺序**：先弹出的是右操作数，后弹出的是左操作数。减法除法尤其要小心。
- **`stoi` 学的不是函数，是「字符串→数字」的正确观念**：必须解析整串，而不是取一个字符强转。
  字符和数值之间的桥是 `c - '0'`，不是 `(int)c`。
- **`tokens[i][0]` → `tokens[i].back()` 能修好崩溃，是个巧合而非原则**：
  因为题目里运算符都是单字符、数字都以数字结尾，取末字符刚好能把负数 `"-11"` 和减号 `-` 区分开，
  消除了「误判成运算符 → 空栈弹栈 → 越界」这条路径。
  **本质修法是用 `t.size() == 1 && 白名单` 显式判断**，这才是任何输入下都不崩的写法。
- **学会了读 ASan 报错**：`heap-buffer-overflow` + 「地址在分配区前 N 字节」基本就是**空容器越界**的指纹。
- 合法输入不该崩，如果崩了，说明**分类逻辑错了**——错误代码路径被"歪打正着"掩盖了，只在边界才暴露。
