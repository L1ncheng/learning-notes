### 主题一：函数的独占时间（LeetCode 636）

#### 1. 题目在问什么

给 `n` 个函数和一串日志 `"id:start|end:timestamp"`（按时间递增）：
`start` = 压栈（开始执行），`end` = 弹栈（结束执行），栈顶就是**当前正在执行**的函数。
求每个函数**自己真正执行了多少个时间单位**。

| 保证 | 含义 |
|---|---|
| 单线程 | 时间轴可以被**无重叠地切分**，每个时刻只属于一个函数 |
| 有 start 必有 end | 栈最终一定弹空，每个时间片都能落实到一个函数头上 |

#### 2. 本题最大的坑：时间戳的两个语义

| 日志 | 语义 | 占不占这个时间点？ |
|---|---|---|
| `0:start:2` | 在时间戳 **2 的起始**开始执行 | ✅ 占 |
| `0:end:5` | 在时间戳 **5 的末尾**结束执行 | ✅ **也占** |

**start 和 end 指向的时刻都属于这个函数**，只有「函数之间的空隙」不属于任何人。
示例 1（`n=2, ["0:start:0","1:start:2","1:end:5","0:end:6"]`）的时间轴：

```
时刻 t :   0   1   2   3   4   5   6
执行者 :   0   0   1   1   1   1   0
           └─ 2 秒 ─┘ └─── 4 秒 ───┘ └1秒┘
```

答案 `[3, 4]`。**所以 `start` 不加 1（半开区间），`end` 必须加 1（闭区间）。**

#### 3. 核心思路：`prev` 记账法

不去管"函数是什么"，只维护 `prev` = **上一次时间轴发生变化的时刻**：
每一段 `[prev, ...]` 的时间，永远归**当前栈顶**。

| 事件 | 结算 | 更新 |
|---|---|---|
| `id:start:t` | 栈非空则 `res[栈顶] += t - prev`（半开 `[prev, t-1]`） | `push(id)`；`prev = t` |
| `id:end:t` | `res[栈顶] += t - prev + 1`（闭区间 `[prev, t]`） | `pop()`；`prev = t + 1` |

> `prev = t + 1` 是灵魂：**t 这一刻已经被弹出去的那个函数占用了**，父函数必须从下一时刻重新计时。

示例 3（`n=2, ["0:start:0","0:start:2","0:end:5","1:start:6","1:end:6","0:end:7"]`）逐条走：

| 日志 | 给谁结算 | res（函数0, 函数1） | prev | 栈（底→顶） |
|---|---|---|---|---|
| `0:start:0` | 栈空，不结算 | `[0, 0]` | 0 | `[0]` |
| `0:start:2` | res[0] += `2-0` = 2 | `[2, 0]` | 2 | `[0, 0]`（递归） |
| `0:end:5` | res[0] += `5-2+1` = 4 | `[6, 0]` | **6** | `[0]` |
| `1:start:6` | res[0] += `6-6` = 0 | `[6, 0]` | 6 | `[0, 1]` |
| `1:end:6` | res[1] += `6-6+1` = 1 | `[6, 1]` | **7** | `[0]` |
| `0:end:7` | res[0] += `7-7+1` = 1 | `[7, 1]` ✅ | 8 | `[]` |

#### 4. 四种写法（互为验证）

| 方案 | 栈里存什么 | 关键动作 | 代码量 |
|---|---|---|---|
| ① `prev` 记账 | 只存 id | end 后 `prev = t + 1` | 最短 ✅ |
| ② 栈帧自带开始时刻 | id + `startAt`（两个同步栈） | end 后 `startAt.back() = t + 1` | 中 |
| ③ `root` 数组记账 | 只存 id，开始时刻记在 `root[id]` | start 覆盖 / end 写回 `root[父] = t+1` | 中 |
| ④ 逐单位暴力 | — | 每个整数时刻给栈顶 +1 | 只用于对拍 |

```cpp
// 方案①：prev 记账（推荐）
vector<int> exclusiveTime(int n, vector<string>& logs) {
    vector<int> res(n, 0), st;
    long long prev = 0;
    for (const string& log : logs) {
        size_t p1 = log.find(':'), p2 = log.find(':', p1 + 1);
        int  id      = stoi(log.substr(0, p1));
        bool isStart = (log.compare(p1 + 1, 5, "start") == 0);
        long long t  = stoll(log.substr(p2 + 1));
        if (isStart) {
            if (!st.empty()) res[st.back()] += (int)(t - prev);   // 半开，不加 1
            st.push_back(id); prev = t;
        } else {
            res[st.back()] += (int)(t - prev + 1);                // 闭区间，含 t
            st.pop_back(); prev = t + 1;                          // 父函数从 t+1 恢复
        }
    }
    return res;
}
```

> **方案③ 的递归为什么不出错**：`root[id]` 只需要记「该 id 当前最内层那一帧」的开始时刻。
> 内层 `start` 覆盖它，内层 `end` 时又写回 `t+1` 还给外层 —— 外层的信息自然回来了。

#### 5. 验证结论（本机无 g++，用 Python 等价实现跑）

- 8 个用例全 PASS（三示例 + 非 0 起点 + 三层嵌套 + 最大时间戳 1e9）
- **3000 / 4000 组随机嵌套日志对拍：0 处不一致**
- 暴力版按"每个整数时刻给栈顶 +1"独立实现，与三种 O(L) 解法结果完全一致

#### 6. 复杂度

| 项 | 复杂度 |
|---|---|
| 时间 | **O(L)**，L = `logs.length`（每条日志 O(1)） |
| 空间 | **O(n + S)**，S = 最大栈深 |

### 主题二：字符串解析 —— 从 string 里提取信息

#### 1. 三次踩坑，同一个根因

| 题 | 我写的 | 实际拿到 | 表现 |
|---|---|---|---|
| LC 150 | `(int)tokens[i][0]` | `'2'` → **50** | 栈里全是 ASCII |
| LC 636 v1 | `(int)logs[i][0]` | `'0'` → **48** | `root[48]` 越界 → ASan |
| LC 636 v1 | `(int)logs[i][8]` | ASCII + 越界 | 时间戳静默变垃圾 |

**根因：把字符串当数组用，把字符当数字用。**

#### 2. 三步套路：定位 → 切分 → 转换

以 `s = "12:start:345"` 为例：

```cpp
size_t p1 = s.find(':');            // 1   定位
size_t p2 = s.find(':', p1 + 1);    // 7
s.substr(0, p1);                    // "12"      切分（第二参是长度！）
s.substr(p1 + 1, 5);                // "start"
s.substr(p2 + 1);                   // "345"
int  id = stoi(s.substr(0, p1));    // 12        转换
long long t = stoll(s.substr(p2 + 1));
```

**这三行和字段多长、编号几位、时间戳几位完全无关** —— 这就是它和 `logs[i][8]` 的本质区别。

#### 3. 四种写法对照

| 写法 | 代码量 | 速度 | 适合 |
|---|---|---|---|
| `find` + `substr` + `stoi` | 中 | 快 | **默认首选** |
| `stringstream` + `getline(ss, tok, ':')` | 中 | 较慢 | 字段多、格式松散 |
| `sscanf("%d:%15[^:]:%lld", ...)` | 短 | 快 | 格式严格固定 |
| 手写扫描（`c - '0'`） | 长 | 最快 | 竞赛、性能敏感 |

#### 4. `char` ≠ 数字：唯一的桥是 `c - '0'`

| 字符 | ASCII |
|---|---|
| `'0'` | 48 |
| `'7'` | 55 |
| `'9'` | 57 |
| `':'` | 58（正好紧挨 `'9'`） |

- `(int)'7'` = **55**（ASCII 码，不是 7）
- `'7' - '0'` = **7** ✅（`'0'~'9'` 在 ASCII 里连续）
- ⚠️ `c - '0'` **只能处理一位数**：本题 `n ≤ 100` 编号可能是 `11`，时间戳到 1e9 有 10 位
  → 必须整段 `stoi` / `stoll`

#### 5. 四个必背的坑

| 坑 | 正确认知 |
|---|---|
| `s.substr(8, 2)` | 第二参是**长度** 2，不是结束下标；`s.substr(8)` 才到末尾 |
| `s.find('@')` | 找不到返回 **`string::npos`**；别写 `if (s.find('@'))`（下标 0 也是"假"） |
| `stoi("123abc")` | 返回 **123，不报错**，只解析前缀；要校验就传 `size_t* pos` |
| `stoi("abc")` | **抛异常**（`invalid_argument` / `out_of_range`），不是返回 0 |

补充：C++17 的 `std::from_chars` 不分配、不抛异常、能用 `ec` / `ptr` 精确判断错误。

#### 6. 顺手的通用工具

```cpp
vector<string> split(const string& s, char delim) {
    vector<string> out; string cur;
    for (char c : s) {
        if (c == delim) { out.push_back(cur); cur.clear(); }
        else            { cur += c; }
    }
    out.push_back(cur);          // 别忘了最后一段
    return out;
}
```

### 主题三：错题复盘 —— 从 LC 150 到 LC 636 的反复错误

#### 1. 错误总清单

**A 类：字符串解析（4 次，同一根因）**
`(int)tokens[i][0]`（LC 150）· `(int)logs[i][0]` → `root[48]` 越界 · `(int)logs[i][8]` 写死下标 ·
`logs[i][2]` 写死下标（编号 ≥ 10 就失效）· **`pd == "start"`**（`char[16]` 退化成指针，比的是地址，恒 false）

**B 类：容器与边界（同一个坑第 2 次）**
`a.back()` / `root[top]` / `stack.back()` 在**空容器**或**非法下标**上取值 →
两次 `heap-buffer-overflow`。栈空是**合法场景**：① 程序刚开始（第一条日志是 `start`，没有父函数）；
② 顶层函数结束、下一个还没开始的**间隙**。

**C 类：区间语义**
`start` 也 `+1`（应为 `t - root`）· `end` 后 `prev = t`（应为 `t + 1`）。
记法：**start 是抢班，end 是交班 —— 交班的人要把最后一秒干完。**

**D 类：工程习惯**
变量名 `stack` / `size` 遮蔽 std 名字 · 拿"编译通过"当"逻辑正确" · 不读 ASan 报告尾部 ·
靠"特殊处理第一条日志 + 初值 0"蒙对 · 不设计最小用例就直接跑长用例。

#### 2. 两轮代码批改（含 ASan 定位）

**v1：硬编码下标版** → `solution.cpp:17:31`，`READ of size 4`

```cpp
int t=(int)logs[i][8];          // 时间戳：写死下标 + ASCII
time[top]+=(t-root[top]+1);     // ← 17:31 崩在这：top = (int)'0' = 48
```

**v2：改用 `sscanf` 之后** → `solution.cpp:16:27`，`READ of size 4`

```cpp
int x; char pd[16] = {0}; long long t;
sscanf(logs[i].c_str(), "%d:%15[^:]:%lld", &x, pd, &t);   // 解析对了 ✅
int top=stack.back();      // ← 16:27 崩在这：空栈取栈顶
if(pd=="start")            // ← 元凶：数组名 vs 字符串字面量，恒 false
```

`pd == "start"` 只是 **warning**（`-Waddress`），编译照样通过 → 每条日志都掉进 `else`
→ 每条都 `pop_back()` → 栈被抽干 → 下一条日志在 `stack.back()` 上崩。
实测三个示例**全部崩在 `logs[2]`**，与报告位置完全吻合。

**ASan 三行读法**：

1. `file:line:col` —— 列号能精确到 token（`16:27` 是 `.back()`，`17:31` 是 `root[top]`）；
2. `READ/WRITE of size N` —— N = 元素字节数（4 = `int`），锁定容器类型；
3. 尾部 `located ... N-byte region ... allocated by std::vector<int>` ——
   4 字节 = 1 个 `int` = 只 push 过一次、又被 pop 空的 `stack`。

#### 3. 三个元问题

1. **「记录过」≠「掌握」**：ASCII 坑在 LC 150 已写进笔记并标 ✅ 已掌握，636 又踩一遍。
   → 能不看笔记默写 + 换题验证，才算掌握。
2. **调试顺序是反的**：应先「最小用例不崩」→ 再「三个示例全对」→ 最后才谈边界与优化。
   而且 **ASan 只报第一处**越界：修完 A 才暴露 B，修完 B 才看到 C，崩溃是分层的。
3. **对"合法输入"的假设太强**：我默认了编号一位数、时间戳一位数、栈不空、首条日志从 0 开始、
   字段位置固定 —— **题目一条都没保证**（只给 `n ≤ 100`、`t ≤ 1e9`、时间递增、有 start 必有 end）。

#### 4. 提交前自检清单（7 条）

| # | 检查 | 反例 → 正解 |
|---|---|---|
| 1 | 有 `(int)` 强转字符？ | `(int)s[0]` → `s[0]-'0'`（一位）或 `stoi(substr)`（多位） |
| 2 | 有写死下标？ | `logs[i][8]` → `find(':')` + `substr` |
| 3 | `char[]` 和字面量 `==`？ | `pd=="start"` → `strcmp` / `string(pd)` |
| 4 | `.back()/.top()` 前判空了？ | `int top=st.back();` → `if(!st.empty())`；只有 `end` 才取 `top` |
| 5 | 数据允许几位？ | `n≤100` → 两位；`t≤1e9` → 十位 |
| 6 | 区间开还是闭？ | `start`: `t-root`；`end`: `t-root+1` |
| 7 | 跑过最小用例？ | `n=1, ["0:start:0","0:end:0"]` → `[1]` |

**批改后可直接提交的版本**（保留我自己的 `root` / `time` 双数组结构）：

```cpp
class Solution {
public:
    vector<int> exclusiveTime(int n, vector<string>& logs) {
        vector<int> res(n, 0);
        vector<int> root(n, 0);      // root[id] = id 当前最内层栈帧的开始时刻
        vector<int> st;              // 栈：只存解析出来的 int 编号

        for (const string& log : logs) {
            int id = 0; char type[16] = {0}; long long t = 0;
            sscanf(log.c_str(), "%d:%15[^:]:%lld", &id, type, &t);

            if (strcmp(type, "start") == 0) {                 // ★1 修掉指针比较
                if (!st.empty())                              // ★2 start 时栈可以为空
                    res[st.back()] += (int)(t - root[st.back()]);   // ★3 半开区间，无 +1
                st.push_back(id);
                root[id] = (int)t;
            } else {
                res[id] += (int)(t - root[id] + 1);           // 闭区间，含 t
                st.pop_back();
                if (!st.empty()) root[st.back()] = (int)t + 1;      // 父函数从 t+1 恢复
            }
        }
        return res;
    }
};
```

## 🔍 难点与解决

| 问题 | 原因 | 解决办法 |
| :--- | :--- | :--- |
| ASan `heap-buffer-overflow, READ of size 4` @ `17:31` | `(int)logs[i][0]` 拿到的是 ASCII `48`，`top=48` 去索引只有 `n` 个元素的 `root` | 解析必须用 `find` + `stoi`，不能用 `(int)` 强转字符 |
| ASan 同型报错 @ `16:27`（改 `sscanf` 之后） | `pd="start"` 是 `char[16]`，`pd=="start"` 比的是**地址**恒 false → 全走 `else` → 每条日志都弹栈 → 下一条在空栈上 `back()` | `strcmp(pd,"start")==0` 或 `string(pd)=="start"`；且 `top` 只在 `end` 分支取 |
| `start` 事件多算 1 秒 | `start` 我写成闭区间 `t-root+1`，应为半开 `t-root` | 实测 `[4,4]` / `[10]` / `[9,1]` → 去掉 `+1` 后 `[3,4]` / `[8]` / `[7,1]` |
| 递归调用（示例 2）怎么区分层 | 用"在不在运行"的布尔数组无法表达多层嵌套 | 必须用栈，一层一个栈帧；`root[id]` 记"最内层那一帧"即可 |
| 首条日志时间戳不是 0 就错 | 特殊处理 `logs[0]` + 依赖 `root` 初值 0 蒙对 | 循环里统一处理，不搞特例 |

## ✅ 今日总结

- **算法骨架我其实一直是对的**（`root` 记账 + `end` 后设 `t+1`），输的全是**"数据的形状"**：
  字符不是数字、字符串不是数组、数组名不是字符串、栈不保证非空、区间不保证闭。
- **`start` / `end` 指向的时刻都属于函数自己**：`start` 半开（不加 1）、`end` 闭区间（加 1），
  而且 `end` 之后父函数要从 **`t+1`** 才恢复。
- **解析日志只有一种可靠写法**：`find(':')` 定位 + `substr` 切分 + `stoi/stoll` 整段转换；
  写死下标（`logs[i][8]`）和 `(int)` 强转字符都是定时炸弹。
- **`char[]` 不是 `string`**：`pd == "start"` 比的是地址，永远 false，而且只是 warning ——
  **编译通过 ≠ 语义正确**。
- **ASan 的行列号能精确到 token**，报告尾部的 region 字节数能直接锁定是哪个 `vector`
  —— 这两条比"猜哪里错了"快得多。
