| v1 | 首版：`vector<int> right;` **没开大小** | 💥 UB | `right[i]=i` 越界写；`s1` 判断写成 `s`，空栈取 `top()` |

| v4 | 修掉笔误改成 `right[i]` | **18** | 赋值位置错（取到"被弹出者"）→ 从**低估**翻成**高估** |

每一版都能编译、都能过 `[2,2]`，但只有最后一版是对的。
**这说明"能跑通简单样例"根本不构成验证。**

#### 2. 知识点零：先明确"栈要产出什么" —— 一个边界数字

写单调栈之前先把**产出**定下来，后面所有争议（赋值写在哪、空栈怎么办）就都变成了推论：

| 要产出的东西 | 怎么说 |
|---|---|
| **产出** | `left[i]` / `right[i]` = **一个下标数字**（一个边界） |
| **来源** | `st.top()` —— **弹完之后幸存的那个**（不是被弹出的） |
| **空栈的含义** | **没有边界**：左边 / 右边没有任何柱子挡住我 |
| **空栈的写法** | 用**哨兵**表示"不存在"：左填 **`-1`**，右填 **`n`** |

```cpp
left[i]  = st.empty() ? -1 : st.top();      // 左边没有更矮的 → -1
right[i] = st.empty() ?  n : st.top();      // 右边没有更矮的 → n
```

**为什么哨兵恰好是 `-1` 和 `n`**：宽度公式 `right[i] - left[i] - 1` 对应真实下标范围
`[left[i]+1, right[i]-1]`，填上哨兵后公式自动退化出正确宽度，**四类情形全部免特判**：

| 情形 | left | right | 宽度 | 含义 |
|---|---|---|---|---|
| 两边都有更矮的 | `1` | `4` | `4-1-1 = 2` | 只在 2~3 之间 |
| 左边没有 | `-1` | `4` | `4-(-1)-1 = 4` | 一直延伸到下标 0 |
| 右边没有 | `1` | `n` | `n-1-1` | 一直延伸到 `n-1` |
| 两边都没有（全局最矮） | `-1` | `n` | `n-(-1)-1 = n` | 整条数组 |

`[2,1,5,6,2,3]` 的 `i=1 (h=1)` 就是第 4 种：`left=-1, right=6` ⟹ 宽 `6`、面积 `1×6=6`
（`1` 是最矮的，除了它自己谁都挡不住它）。

> **"栈空"不是异常，不是需要打补丁的边界情况 —— 它本身就是"没有边界"这个合法答案。**
> 这也从另一个角度解释了赋值为什么必须在 `while` 之后：只有循环结束，
> 才知道该填 `st.top()` 还是该填哨兵。

#### 3. 知识点一：边界只能来自"幸存者"

**逻辑证明（不靠直觉）**

```cpp
while (!st.empty() && heights[st.top()] >= heights[i]) st.pop();
```

- 被 `pop()` 掉的 `t` 一定满足 `heights[t] >= heights[i]`（弹它的条件）；
- 边界的定义是 `heights[boundary] < heights[i]`（必须**严格更矮**才算挡住我）。

两个集合**交集为空** ⟹ 边界**绝不可能**出现在被弹出的元素里。
所以 `left[i] = st.top()` 写在 `while` 之内，从条件写下那一刻起就注定是错的，
换任何比较符号都救不回来。

**几何直觉**：把矩形想成一块高度恰好 `h[i]` 的方块往两边推 ——

| 遇到的柱子 | 结果 |
|---|---|
| 比它**高** | 方块从它身上穿过去，**不挡路** |
| 比它**矮** | 撞墙，**必须停** |

被弹出来的正是"高柱子"，**恰恰是不挡路的那批**；栈顶留下的才是第一堵墙。

**栈顶为什么是"最近"的**：栈内下标递增、高度递增；弹完之后栈顶是唯一剩下的
`< h[i]` 的候选，同时也是下标最大的那个 ⟹ 它就是**最近**的边界。

**还有一个致命点**：`while` 可能把整个栈弹空 —— 那就**根本没有边界**，
端点该填 `0`（边界语义下填 `-1`）。"有没有边界"这个信息，
**只有在循环结束的那一刻才确定**，所以"边界的前一个"在循环体内部是**未定义**的。

#### 4. 知识点二：栈上相邻 ≠ 数组相邻（今天想最久的一个）

一个非常自然的想法：

> "最后被弹出的那个，不就是边界的前一个吗？记它不就行了？"

**在栈的意义上这是对的** —— 最后被弹出的确实是"边界在栈中的上邻"。
**但它不等于 `边界 + 1`。** 因为夹在中间的那些下标，早在**之前的轮次**就被弹掉了：
它们不在栈里，却实实在在还在数组中。

**反例：`[1, 3, 2, 2]`，看 `i = 3`**

处理到 `i = 3` 时，栈是 `[0(h=1), 2(h=2)]`：

```
top=2, h=2 <= h[3]=2  → 弹出   ← 最后被弹出的就是它，记下 2
top=0, h=1 <  h[3]=2  → 停住   ← 边界是 0
```

- 正确左端点 = `边界 + 1 = 1`（下标 1 高 3 ≥ 2，能盖住）
- 错误记法给出 **2**

原因：下标 1 在 `i = 2` 那轮就被弹掉了 —— 当时 `h[2]=2 <= h[1]=3`。
它在数组里，但不在栈里。

```
栈里:   0 ── 2          （1 已经不在了）
数组:   0    1    2    3
              ↑          ← 存在于数组，消失于栈
```

**深层原因**：单调栈维护的是**左侧记录（left records）**，索引 1（高 3）被索引 2（高 2）取代，
因为"更矮且更靠右"对未来任何 `i` 都更有挡路能力，索引 1 永远不可能再当谁的边界了。
这个剪枝是 `O(n)` 的根源，**代价就是位置信息被压缩** —— 所以绝不能用栈上的相对关系去推算数组下标。

**危险之处**：这种记法只会**偏大**（`p1 > 边界`）→ 宽度偏小 → **答案被低估，且不报错**。

#### 5. 知识点三：两套自洽语义，三处必须统一

同一个弹栈事件有两种自洽记法，**默认值 / 赋值位置 / 赋值对象 / 宽度公式**必须整组选：

| | A. 边界语义（推荐） | B. 端点语义 |
|---|---|---|
| `left[i]` 含义 | 左边第一个更矮的**下标** | 最左能延伸到的**下标** |
| 缺省值 | `-1` / `n` | `0` / `n-1` |
| 赋值位置 | **`while` 之外** | **`while` 之内** |
| 赋值对象 | 当前元素 `i` | **被弹出者** `st.top()` |
| 内层写法 | `left[i] = st.empty() ? -1 : st.top();` | `right[st.top()] = i - 1;` |
| 收尾 | 不需要（空栈即哨兵） | 需要把栈里剩下的补 `n-1` / `0` |
| 宽度公式 | `right[i] - left[i] - 1` | `right[i] - left[i] + 1` |

B 内层的逻辑是：
> "`t` 往右看，第一个比它矮的是 `i`，所以 `t` 的右端点最高只能到 `i-1`。"

**信息属于 `t`，不属于 `i`。** 写成 `right[i] = st.top()` 就是把主语写反了 ——
本该"我给别人当边界"，变成了"别人给我当边界"。

> **统一结论**：弹栈这一个动作产生的是"**被弹出者的信息**"。
> - 想记成**边界** → 在 `while` **外**记给 `i`；
> - 想记成**端点** → 在 `while` **内**记给被弹出者；
> - **绝不能记成"当前元素的下标"。**

我前几版踩的正是"**默认值和公式用 B、赋值位置用 A**"的混合态。

#### 6. 条件的字面统一（v6 的那一个符号）

```cpp
// 第一轮（从左往右求 left）—— 正确
while (!s.empty() && heights[s.top()] >= heights[i]) s.pop();

// 第二轮（从右往左求 right）—— 曾经写成反向
while (!s1.empty() && heights[i] >= heights[s1.top()]) s1.pop();   // ✗ 弹出的是"比我矮的"，正是边界
while (!s1.empty() && heights[s1.top()] >= heights[i]) s1.pop();   // ✓ 与第一轮完全对称
```

**定死规矩**：

> 条件永远写成 `heights[st.top()] >= heights[i]`（`heights[栈顶]` 放左边），
> `st.empty() ? 哨兵 : st.top()` 的赋值永远写在 `while` 之后。
> 两轮照着抄，就不会再翻车。

**为什么会写反**：从左往右扫时"当前元素"天然在栈顶右边，写 `heights[i] <= heights[s.top()]`
时脑子里是"我比左边最近的矮吗"；到了从右往左扫，栈顶跑到了当前的**左边**，
就下意识把主语换成了 `heights[i]` —— 但单调栈的不变式在两侧是对称的，条件不该跟着换。

**反向条件的实际后果**：`heights[i] >= heights[s1.top()]` 弹掉的是"比我矮"的元素，
留下"比我高"的 ⟹ 实际在求"右边第一个比我**高**的柱子"。
于是 `[2,1,5,6,2,3]` 的 `i=3 (h=6)`：右边 2 和 3 都 ≤ 6，全被弹空，`right[3] = n = 6`，
宣称高度 6 能横跨下标 3~5 —— 可 `h[4]=2`，矩形被戳穿，算出 `6×3 = 18`。

#### 7. 4 条自检不变量（打印 `left/right` 后逐条核对）

```
1. left[i] <= i <= right[i]                              // 下标自洽
2. heights[left[i]]  < heights[i]   （无边界则 left  = -1）
3. heights[right[i]] < heights[i]   （无边界则 right = n）
4. left[i]..i 之间没有比 heights[i] 更矮的；i..right[i] 之间同理
```

**第 4 条是"第一个 / 最近"的直接翻译。**
今天所有坑都来自同一个错误：**把"最远的那个"当成了"最近的那个"**。

> 第 2 条只能查出"它不是边界"，查不出"它是不是**第一个**边界" ——
> 必须第 4 条才能抓出"相邻"被破坏的情况。

#### 8. 失败模式的两个方向

| 失败模式 | 触发写法 | 后果 | 是否报错 |
|---|---|---|---|
| **低估** | 把"被弹出者/最远的"当边界 → 宽度偏小 | 答案偏小 | 不报错，静默 |
| **高估** | 比较符号反了 → 弹掉了真正的边界 | 答案偏大（出现**不可能存在**的矩形） | 不报错，静默 |

**两者都不会崩、都不会编译报警**，所以只能靠**用例设计**兜住。

#### 9. 测试用例设计（今天最大的教训之一）

| 用例 | 期望 | 专抓什么 |
|---|---|---|
| `[2,2]` | 4 | 等高元素互相弹 → ⚠️ **今天有 4 个错误版本都能过它** |
| `[1,3,2,2]` | 6 | "最远当成最近"（栈上相邻 ≠ 数组相邻） |
| `[2,1,5,6,2,3]` | 10 | 中间夹矮柱子 → 抓**高估** |
| `[1]` / `[0]` | 1 / 0 | 边界情况 |

结论：**只拿 `[2,2]` 这种"没有中间矮柱子"的用例自测，会得到虚假的安全感。**
必须准备一个"峰值两侧都有更矮柱子"的用例。

## 💻 代码与实践

### 最终正确解（边界语义）

```cpp
class Solution {
public:
    int largestRectangleArea(vector<int>& heights) {
        int n = heights.size();
        if (n == 0) return 0;

        vector<int> right(n), left(n);
        stack<int> s, s1;                                 // 两个栈：一个求左，一个求右

        for (int i = 0; i < n; i++) {                     // 从左往右 → 左边界
            while (!s.empty() && heights[s.top()] >= heights[i]) s.pop();
            left[i] = s.empty() ? -1 : s.top();           // while 之外，主体是 i
            s.emplace(i);
        }
        for (int i = n - 1; i >= 0; i--) {                // 从右往左 → 右边界（条件完全对称）
            while (!s1.empty() && heights[s1.top()] >= heights[i]) s1.pop();
            right[i] = s1.empty() ? n : s1.top();
            s1.emplace(i);
        }

        int ans = 0;                                      // 别叫 max，会遮蔽 std::max
        for (int i = 0; i < n; i++) {
            ans = std::max(ans, heights[i] * (right[i] - left[i] - 1));
        }
        return ans;
    }
};
```

**验收**：`[2,1,5,6,2,3]` → `left = [-1,-1,1,2,1,4]`，`right = [1,6,4,4,6,6]`，
`i=2` 得 `5 × (4-1-1) = 10` ✅ ｜ `[2,2]` → 4 ✅ ｜ `[1,3,2,2]` → 6 ✅ ｜ `[1]` → 1 ✅

> 变量名 `int max = 0;` 又一次出现（09-17 记过 `stack` / `size` 遮蔽 std 名字）。
> 这版侥幸能编译，是因为没调用 `std::max`；一旦改成 `max(ans, ...)` 就炸。
> **编译通过 ≠ 语义正确**，这条教训要连着记。

## 🔍 难点与解决

| 问题 | 原因 | 解决办法 |
| :--- | :--- | :--- |
| `vector<int> right;` 后直接 `right[i]=i` | 空 vector 越界写，UB | 声明时就给大小：`vector<int> right(n), left(n);` |
| 第二个循环判 `!s.empty()` 却取 `s1.top()` | 第一轮结束后 `s` 非空而 `s1` 为空 → 空栈 `top()` | 条件与所取的栈必须对应；两轮各用一个栈就不用清空 |
| `right[i] = s.top()` 写在 `while` 内 | 取到的是**被弹出者**（高度 ≥ `h[i]`），按定义不可能是边界 | 赋值挪到 `while` **之外**，取幸存栈顶；空栈填哨兵 |
| "最后被弹出的就是边界+1" | 栈上相邻 ≠ 数组相邻：中间下标早被弹掉，不在栈里但仍在数组中 | 只记**边界本身**（栈顶），不要记"边界的邻居" |
| `while` 内不知道边界是否存在 | 循环可能把整个栈弹空 | 哨兵在**循环结束后**统一处理：`st.empty() ? -1 : st.top()` |
| 出现**负面积** | 默认值用端点语义（`i`）、赋值为边界语义、公式用端点语义（`+1`），三者打架 | 选定一套语义，**默认值 / 赋值位置 / 参数 / 公式四处一起改** |
| 两轮条件不对称 → 算出 18 | 第二轮写成 `heights[i] >= heights[s1.top()]`，弹掉的是真正的边界，留下"更高的" | 两轮都写 `heights[st.top()] >= heights[i]`，字面完全一致 |
| `int max = 0;` | 遮蔽 `std::max` | 改名 `ans` |
| `[2,2]` 能过但 `[2,1,5,6,2,3]` 是 18 | 简单用例无法暴露"高估" | 用例必须包含"峰值两侧都有更矮柱子"的形状 |

## ✅ 今日总结

- **算法的"形"我早就会了**（单调栈、两轮扫描、弹栈定边界），输的全是**"信息属于谁"**：
  弹栈产生的是**被弹出者**的信息，我却一直往**当前元素**头上记。
  主体一错，后面默认值、公式怎么补都是在补一个错的东西。
- **今天想最久的一句话**：
  > 最后被弹出的元素 = 边界在**栈中**的上邻，但 **≠ 边界 + 1**。
  > 因为单调栈的剪枝专门把"用不上"的下标提前弹掉，**栈里相邻，不等于数组里相邻**。
- **弹栈的条件本身就判了死刑**：被弹出者 `>= h[i]`，边界 `< h[i]`，
  两个集合交集为空 —— 不用几何直觉也能证明边界不可能来自被弹出者。
- **`while` 之外还有一层原因**：循环体内部连"边界是否存在"都不知道（可能弹空），
  所以"边界的前一个"这个概念在那一刻是**未定义**的。
- **两套语义要整组选**：边界语义（`while` 外、公式 `-1`）或端点语义（`while` 内、主体是被弹出者、公式 `+1`）。
  混着用就会出现负面积 —— 这是"语义不一致"最典型的信号。
- **比较符号的方向性**：`heights[栈顶]` 永远放左边，
  不要因为扫描方向反了就把 `heights[i]` 提到左边 —— 那是"照着镜像抄"的错误。
- **失败有方向，而且都不报错**：低估（取"最远的"）和高估（弹掉边界）都静默通过编译；
  只有**用例设计**能兜住 —— `[2,2]` 有 4 个错误版本能过，`[2,1,5,6,2,3]` 才行。
- **"记录过"≠"掌握"**（09-17 已写过一次）：`vector` 未开大小、变量名遮蔽 std、
  比较符号方向 —— 这些都是老面孔，今天又各踩一次。
- 顺带把 84 的**知识边界**补上了：以前只会默写模板 B，今天才知道模板里
  `while` 之外那一行**为什么非得在外面**。
- **先定"产出"，再谈写法**：单调栈的产出就是**一个边界下标数字**（`st.top()`），
  而 **"栈空"= 没有边界 = 一个合法答案**，用哨兵 `-1` / `n` 表示。
  想清楚这一点，`while` 的位置和 `? :` 的哨兵都不是"规则"，而是**推论**。
- **哨兵不是魔法数**：`-1` / `n` 恰好让宽度公式 `right - left - 1` 在四类情形下
  自动算出正确答案（无边界 ⟹ 延伸到数组端点），因此**全程零特判**。
